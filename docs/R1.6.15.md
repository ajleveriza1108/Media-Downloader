# R1.6.15 — Internal Media Capture Streaming

## Stream architecture

R1.6.15 uses Microsoft WebView2 as an internal browser/media surface. In Auto mode MediaDock can load the supplied webpage internally, observe eligible HTTP/HTTPS media responses, classify direct video/audio plus HLS `.m3u8` and DASH `.mpd` manifests, ignore common segment requests, and look for a live `<video>` element created by site JavaScript.

When a supported video element is found, MediaDock can keep the site's own browser playback engine while hiding surrounding page UI and expanding the video inside the Stream workspace.

## Resolution and controls

The Stream UI includes Auto internal detection plus direct combined non-DRM resolutions exposed by yt-dlp. It also includes Play, Pause, Stop, Volume, Full Screen, MP4, and MP3 controls.

MP4/MP3 actions use the normal download queue and existing trial accounting.

## Retained ingestion

R1.6.14 drag-link ingestion and TXT/CSV batch import remain cumulative.

## Verification boundary

The generated package passed static/source/package checks, but Windows-only build/runtime verification remains pending. Do not treat R1.6.15 as stable until those Windows gates pass.

## Access boundary

MediaDock does not bypass DRM, paywalls, authentication, subscriptions, or other protected access. Server-side/in-stream ads are not guaranteed to be removable.
