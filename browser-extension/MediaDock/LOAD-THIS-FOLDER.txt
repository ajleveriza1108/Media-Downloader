R1.6.56 browser-grabber changes:
- The floating "Download this video" control appears only when media is detected.
- Drag the floating control to reposition it. Its position is remembered.
- Open the panel and resize it from the lower-right edge. Its size is remembered.
- Detects direct MP4/WebM/audio media, HLS (.m3u8), DASH (.mpd), DOM media sources, page fetch/XHR traffic and PerformanceResourceTiming entries.
- Detection runs inside embedded frames too, while only the top page displays the grabber.
- Each detected item keeps the originating frame as its referrer, improving handoff on sites whose media requests depend on the embedded-player page; extensionless <video>/<audio> URLs are also recognized.
- HLS master manifests are expanded into quality/bitrate variants when the manifest is readable.
- Per-tab candidate state is kept in chrome.storage.session so Manifest V3 service-worker suspension does not erase the list.
- Segment noise and duplicate URLs are filtered before display.
- A complete-page analysis fallback remains available when MediaDock can see the player but not a stable direct stream URL.
- No browser-wide webRequest permission is used.
